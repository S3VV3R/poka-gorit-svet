# Пока горит свет

Текущая версия: **v1.1.4**. Изменения: `CHANGELOG.md`.

Самостоятельная папка игры для статического хостинга, в том числе GitHub Pages.
Сборка, серверная часть, CDN и установка пакетов для публикации не нужны.
Прежний большой HTML больше не является исходником этого проекта: меняйте файлы здесь.

## Исправление уборки в главе 5 — v1.1.4

При задании «Закончить уборку на кухне» можно выбрать «Мыть посуду» в «Чем заняться?»
или воспользоваться отдельной кнопкой сюжетного задания вверху списка. Также
работают взаимодействия у раковины и кухонного стола: на подсказке будет «· сюжет».
Выполненные действия ужина больше не перехватывают взаимодействие.

Для продолжения сохранённого прохождения обновите всю папку игры и нажмите
«Продолжить», не «Новая игра». Сохранение v1.1.3 после ссоры с Беллой или родителями
восстановит нужное задание без повторения начала главы. Если меняется адрес сайта
или браузер, предварительно скачайте прогресс через «Сохранения» и импортируйте
его в новой версии. Подробности проверки — `QA-v1.1.4.md`.

## Сохранения, обучение и текст

Кнопка «Сохранения» есть в главном меню и на паузе. Автосохранение обновляется игрой,
три ручных слота — только по команде игрока. Продолжение начинается с контрольной
точки сцены, не с точного положения персонажа или середины реплики.
Перед новой игрой, загрузкой другого прогресса и перезаписью занятого слота
появляется подтверждение. Копия «Перед заменой прогресса» хранит последнее
заменённое прохождение или слот; следующая замена обновит её. Есть также
предыдущее автосохранение для восстановления при повреждении основного.

«Скачать текущий прогресс» создаёт переносимый JSON-файл. На другом устройстве
выберите его в разделе «Импорт сохранения из файла», затем ручной слот и «Загрузить».
Импорт проверяет структуру файла до записи; ограничение — 8 МБ. Это локальные
сохранения, не облачная синхронизация. Очистка данных браузера удалит слоты,
поэтому важный прогресс лучше скачать. Данные локального файла, localhost и
GitHub Pages могут храниться раздельно — переносите их через файл.

Обучение объясняет движение, действие и «Чем заняться?» после начала игры.
Его можно скрыть или повторить в настройках. Продолженным старым прохождениям
подсказки не навязываются. В настройках и паузе доступны размер текста с примером
и скорость его появления. Пропуска и мгновенного раскрытия реплик нет.
Настройки звука и текста запоминаются отдельно от сюжетных контрольных точек.
Если браузер запрещает запись, новую игру всё ещё можно начать в памяти и скачать
прогресс файлом. При закрытии вкладки несохранённый прогресс будет потерян.
Замена уже начатого прохождения блокируется, если не удалось записать его копию.

## Телефоны, планшеты и производительность

На телефонах и планшетах требуется горизонтальное положение. В вертикальном положении сначала
показывается предупреждение с анимацией поворота телефона; движок запускается после
поворота автоматически. Повторный поворот в вертикальное положение приостанавливает
активные сцены, а не перезапускает игру. Мир сохраняет пропорции,
а меню и диалоги отображаются отдельно от игрового холста: текст не уменьшается вместе
с картинкой. Основные кнопки имеют высоту не менее 48 CSS-пикселей, текст диалогов —
не менее 17 CSS-пикселей. Длинные записи, варианты выбора и меню можно прокручивать.
Учитываются безопасные края экрана и доступная высота окна браузера.

На сенсорных устройствах появляются джойстик и кнопка «Действие».
Их можно удерживать одновременно. Отпускание, отмена касания, смена размера окна
и потеря фокуса сбрасывают ввод, чтобы персонаж не продолжал двигаться сам.
«Сделать снимок» доступно в меню паузы даже на маленьком экране.

В настройках и на паузе можно выбрать автоматический режим, экономный (30 кадров/с)
или плавный (60 кадров/с). Проверка устройства определяет примерный тип, сенсорный ввод,
размер окна и доступные сведения о процессоре/памяти. Отсутствующие сведения показаны
как неизвестные. Узкое окно компьютера не считается телефоном. Проверка работает локально.

Автоматический режим начинает с 60 кадров/с и оценивает реальные игровые кадры после
двух секунд прогрева. Две подряд трёхсекундные просадки сначала включают облегчённые
эффекты (половину декоративных листьев/светлячков/бабочек), следующие — лимит 30 кадров.
Меню, скрытая вкладка, вертикальное положение и длинные паузы не участвуют в оценке.
Ограничение сохраняется до повторной проверки или ручного изменения режима, чтобы
качество не колебалось. «Проверка устройства» находится в настройках и паузе.
Слабые аппаратные подсказки уменьшают только эффекты, а не частоту кадров при запуске.

Ограничитель кадров сохраняет дробный остаток времени, не отбрасывая лишние кадры.
Частота обновления не меняет скорость движения и игровых событий. Звук при скрытии
страницы приостанавливается. Снимки в альбоме загружаются по мере приближения к ним.

Проверены десять размеров окна от 320×568 до 3440×1440. Это не гарантия работы на
любом существующем устройстве: старые браузеры, реальные iOS/Android, экранная
клавиатура и быстродействие конкретного телефона требуют отдельной проверки.
Подробности — в `QA-ADAPTIVE.md`. Подготовка для GitHub Pages сохранена.

## Опубликовать на GitHub Pages

1. Создайте репозиторий GitHub. Для бесплатного GitHub Pages используйте публичный репозиторий.
2. Загрузите **содержимое этой папки** в ветку `main`: `index.html` должен лежать прямо в корне репозитория, рядом с `assets`, `js`, `styles`, `vendor` и `.nojekyll`.
3. Откройте **Settings → Pages → Build and deployment**.
4. Выберите **Deploy from a branch**, затем **main** и **/(root)**. Нажмите **Save**.
5. Дождитесь успешной публикации. Откройте ссылку, которую покажет GitHub Pages.

Не загружайте только index.html или ZIP как один файл: нужны распакованные файлы и папки.
Не меняйте регистр имён файлов. Пустой `.nojekyll` отключает обработку Jekyll.
Папки `tests`, `tools` и файлы документации не нужны браузеру, но их можно хранить в репозитории.
Не загружайте `node_modules` и `test-results` — они внесены в `.gitignore`.

Все адреса ресурсов относительные: игра рассчитана и на корень сайта,
и на адрес вида `https://имя.github.io/репозиторий/`.
Реальная публикация в аккаунт GitHub не выполнена: репозиторий и доступ к нему не предоставлялись.

Официальная инструкция: [выбор источника GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Запустить на компьютере

Нужен Node.js 22 или новее. В терминале этой папки выполните:

```sh
npm start
```

Устанавливать зависимости для запуска не требуется. Откройте адрес, который напечатает сервер:
обычно `http://127.0.0.1:8765/`. Для остановки нажмите Ctrl+C.
Если порт занят, в PowerShell используйте `$env:PORT=8766; npm start`.

Простое открытие index.html двойным щелчком (`file://`) не поддерживается:
браузер может блокировать загрузку отдельных изображений. На GitHub Pages этого ограничения нет.

## Где что менять

```text
index.html             — разметка страницы и порядок загрузки скриптов
styles/                — оформление страницы и меню занятий
assets/manifest.js     — имена и относительные адреса изображений
assets/images/         — 275 отдельных PNG
vendor/                — локальная копия Phaser и её лицензия
js/
  core/                — настройки, состояние, сохранения, запуск
  data/                — сюжет, персонажи, достижения, решения
    dialogues/         — отдельный файл диалогов каждого персонажа
  scenes/chapters/     — отдельный файл каждой главы
  ui/                  — диалоги, главное меню и пауза
                         adaptive-*.js — адаптивный интерфейс, ввод и настройки
  entities/            — игрок, NPC, коты
  systems/             — бытовые действия и игровые системы
    chronicle/         — занятия, события, решения, социальные действия
  world/               — окружение, жители, балкон
  integration/         — подключение систем к сценам
  audio/               — звук
  input/               — управление
  main.js              — конфигурация движка и запуск игры
tests/                 — автоматические проверки
tools/                 — локальный сервер и запуск проверок
```

Код разделён по назначению, а изображения и стили больше не встроены в HTML.
Скрипты загружаются через `defer` в фиксированном порядке из index.html.
Это обычные браузерные скрипты с общими именами классов и систем, не ES-модули:
так сохранены существующие взаимодействия без обязательной сборки.
Не переставляйте подключения произвольно; при добавлении нового файла укажите его
после зависимостей и до использующего его кода. Адаптеры из `integration/` подключаются
после систем и сцен. Меню Chronicle разбито на тематические части через `Object.assign`.

## Проверки

Проверки структуры и загрузки по HTTP не требуют сторонних пакетов:

```sh
npm run check
```

Для полного набора проверок установите тестовую зависимость:

```sh
npm install
npm test
```

Проверяются синтаксис, точный регистр имён, все ресурсы из корня и из подпапки
репозитория, меню, диалоги, прежние сохранения, размеры комнат и бытовые действия.
Отдельный тест запускает настоящий Phaser в Node с синтетическими сохранениями:
проверяет переход с балкона первой главы во вторую и повторные переходы через меню.
Это автоматические проверки, а не полный ручной проход игры во всех браузерах.
Перед релизом рекомендуется открыть опубликованную ссылку на целевых устройствах.

## Сохранения

Сохранения остаются в localStorage браузера. Ключ основного сохранения сохранён;
v1.1.3 читает старый формат и записывает новый, с версией и датой. Старые сборки
не рассчитаны на новый формат: перед откатом скачайте копию прогресса.
Сохранения привязаны к адресу сайта: прогресс из старого `file://` или локального
сервера не переносится автоматически на домен GitHub Pages. Другой браузер, очистка
данных сайта или запрет хранения данных также влияют на доступность сохранений.
Облачной синхронизации нет. Старый однофайловый вариант оставлен рядом с проектом
как резервная версия и для работы новой игры не нужен.
